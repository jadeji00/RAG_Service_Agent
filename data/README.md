# 数据说明

## 1. 目录结构

```text
data/
├── 选购指南.txt                  # 选购建议
├── 故障排除.txt                  # 错误码与常见故障
├── 维护保养.txt                  # 日/周/月/季度保养与耗材周期
├── 扫地机器人100问2.txt          # 使用与故障问答
├── 扫拖一体机器人100问.txt       # 拖地与基站问答
├── 扫地机器人100问.pdf           # 第三方 PDF，授权状态不明，不入公开仓库，默认不参与灌库
└── external/
    └── records.csv               # mock 用户月度使用报告
```

## 2. 知识库数据

- 文本文件为 UTF-8，按「标题 + 小节 + 问答」组织。
- 当前切分参数：`chunk_size=200`、`chunk_overlap=20`，分隔符见 `config/chroma.yml`。
- 当前 `allow_knowledge_file_type` 只含 `txt`：PDF 的内容已由两份 txt 覆盖，且它的授权状态不适合公开入库；确需索引 PDF 时再改配置。
- 灌库入口：`python -m rag.vector_store`。启动时也会自动同步：
  - 文件内容未变 → 跳过；
  - 内容变化 → 按 `source` 删除旧 chunk 后重写；
  - 源文件删除 → 清理对应向量；
  - 向量库为空 → 自动重建。
- 去重依据是 chunk metadata 里的 `file_md5`，不再维护外部 `md5.text` 台账。
- 已知规模：排除 PDF 后根库 **66 个 chunk**（2026-11-06 实测），随数据变更会变化；此前含 PDF 时为 113 条。

## 3. 业务 mock 数据

`external/records.csv` 为报告场景的模拟数据：

| 字段 | 含义 |
|---|---|
| `用户ID` | `1001`–`1010` |
| `特征` | 户型、家庭成员、地面材质 |
| `清洁效率` | 覆盖率、异常次数等 |
| `耗材` | 主刷/滤网/边刷/尘袋状态 |
| `对比` | 与上月对比 |
| `时间` | `2026-06` 至 `2026-11` |

评测报告题使用 **`用户ID + 月份`** 唯一定位，例如 `1004 / 2026-10`、`1006 / 2026-07`。

> 这些数据仅用于演示与评测，不代表真实用户。

## 4. 评测标注约定

`eval/dataset.jsonl` 的 gold 标签**不绑定 chunk id**，因为切分策略一变 id 就失效。统一使用：

- `gold_sources`：文件名，如 `故障排除.txt`；
- `gold_sections`：小节标题或题号，如 `一、错误代码`、`E01 碰撞传感器异常`、`Q3`；
- `gold_answer`：可复核的要点，不要求逐字匹配。

召回评测时，来源文件必须命中；有 `gold_terms` 时要求正文覆盖任一关键词，否则要求覆盖指定小节/题号。

## 5. 公开仓库注意事项

- `data/*.pdf` 已在 `.gitignore` 中排除，不提交授权状态不明的第三方资料。
- 五份 txt 是自行整理的通用产品问答（不含任何具体品牌的说明书原文、商标或售后话术），可随仓库公开。换成自己的语料时直接替换文件即可，启动会按 md5 自动重灌，删掉的文件对应向量也会被清理。
- 公开前仍建议自行过一遍语料来源；**如不确定，公开仓库只保留少量自写示例数据，并在 README 说明如何替换**。
- `.env`、`log/`、`chroma_db/`、`checkpoints/` 均不入库。
