# 评测

> 目标：把「检索对不对、答得对不对」变成可复现的数字。当前已完成 **M2 检索升级的四阶段前后对比**、easy / hard 两套检索与回答基线、`--repeat` 的 **pass^k**，以及无证据阈值的 **可复现标定**。
>
> 测试分层、263 个用例与结果说明见 [docs/testing.md](../docs/testing.md)；M2 四阶段对比见该文档 5.13 节，M2 后重跑的 hard pass^3 见 5.18 节，报告延迟剖析见 5.6 节，身份登录与会话归属的实跑见 5.14 节。

## 1. 数据集

两套数据集，schema 相同：

| 文件 | 题量 | 定位 |
|---|---|---|
| `eval/dataset.jsonl` | 80（answerable 55 / negative 15 / report 10） | **easy split**：多数题目接近知识库原问句，用于稳定回归 |
| `eval/dataset_hard.jsonl` | 25（answerable 20 / negative 5） | **hard split**：改写问法、跨章节组合、领域邻近负样本，用于看真实理解 |

easy split 的用途：

| 类型 | 数量 | 用途 |
|---|---|---|
| `answerable` | 55 | 知识库可回答，评检索与回答 |
| `negative` | 15 | 超范围问题，评拒答 |
| `report` | 10 | 按用户/月生成报告，评字段完整性 |

### 字段

```json
{
  "id": "qa-001",
  "type": "answerable",
  "question": "60㎡以下的小户型选扫地机器人，重点看什么？",
  "gold_sources": ["选购指南.txt"],
  "gold_sections": ["一、先明确需求"],
  "gold_terms": ["60㎡以下", "性价比"],
  "gold_answer": "……",
  "tags": ["选购", "小户型"]
}
```

- `gold_sources`：允许的正确来源文件，可多个。
- `gold_sections`：章节标题或题号，如 `二、每周维护`、`Q3`、`【E01 碰撞传感器异常】`。
- `gold_terms`：答案关键词；有它时以关键词为准，避免只命中章节标题。
- **不标 chunk id**：切分策略一变 id 就失效，gold 必须能跨切分复用。

报告题额外有 `user_id`、`month`、`expected_fields`，gold 由 `records.csv` 对应行生成。

## 2. 指标

| 指标 | 定义 |
|---|---|
| Span Recall@k | 前 k 条里是否存在「来源命中 + 答案关键词/章节命中」的片段 |
| Span MRR@k | 首个相关片段排名的倒数均值，未命中记 0 |
| Source Recall@k | 前 k 条里是否出现正确来源文件 |
| 延迟 | 单题检索全链路（embedding + Chroma + BM25 + RRF + 重排）的 P50 / P95 |

每题只有一个 gold 答案集合，所以 **Recall@k 等价于 hit rate**，不是多文档召回率。Span 与 Source 分开报，是为了区分「文件没召回」和「文件召回但段落不对」。

> M2 之后 `retrieve()` 返回的片段来自四段管线，`RagSummarizeService.retrieve_with_stats()` 会额外给出每段的诊断字段（两路候选数、融合后条数、两路重合数、索引指纹、各段延迟、重排是否降级、重排最高分与保留条数）。评测脚本只用文档列表，指标定义没变——**这是刻意的：管线换实现，尺子不动。**

### 回答级指标

`eval/run_answer_eval.py` 对三类题分别计分：

| 指标 | 定义 |
|---|---|
| correctness 0/1/2 | LLM judge 对照 gold answer：2 完全正确、1 部分正确、0 错误/答非所问 |
| faithfulness 0/1/2 | 回答中的事实能否在检索上下文（或 CSV 原始记录）中找到依据 |
| refusal | 负样本是否明确拒答，或说明产品不具备该能力并拉回业务范围 |
| 字段完整率 | 报告是否覆盖 `expected_fields`：每个字段至少命中 1 条事实，且命中率 ≥ 50% |
| 报告忠实率 | 报告中的数字、状态、对比是否来自 CSV；编造记 0 |
| 建议率 | 报告是否给出至少一条针对该用户数据的可执行建议 |
| 报告子流程执行率 | 报告请求是否命中 `is_report_query` 并走确定性 `report_pipeline` |
| `fetch_args_ok` | 取数调的 `user_id` / `month` 是否与题目给定值一致 |
| 通过率 | answerable = correctness ≥ 1 且 faithfulness ≥ 1；negative = refusal = 1；report = 字段完整且 faithfulness ≥ 1 |

报告字段用**确定性规则**核对（标签 + 数值 + 单位归一），不交给模型；语义忠实度才用 LLM judge。这样既能抓住漏字段，也能避免模型「自己判自己」。

### pass^k

同一道题独立跑 k 次（`--repeat k`），每题记录 `pass_count`：

| 指标 | 定义 | 回答的问题 |
|---|---|---|
| 严格 pass^k | k 次全部通过 | 系统是否**稳定**会 |
| 至少一次通过 | k 次里至少 1 次通过 | 系统是否**有可能**会 |
| 平均单次通过率 | `Σ pass_count / (题数 × k)` | 单次运行的期望水平 |
| 波动题 | `0 < pass_count < k` | 哪些题靠运气 |

单次通过率会掩盖不稳定；严格 pass^k 与「至少一次」一起报，才能区分「稳定会」和「碰巧对」。

### 3.2 M2 分阶段对比

四段每改一段都重跑同一套题，结果文件按阶段留档（`*_m2a_chunking` / `*_m2b_hybrid` / `*_m2c_rerank` / `*_m2d_final`）：

| 阶段 | easy Span@1 | easy Span@3 | easy Source@3 | hard Span@1 | hard Span@3 | hard Source@8 | easy 检索 P50 |
|---|---|---|---|---|---|---|---|
| 起点：200 字硬切 + 纯向量 L2 | 65.45% | 94.55% | 100.00% | 55.00% | 80.00% | 90.00% | 126.05 ms |
| ① QA 感知切分（+cosine） | 67.27% | **87.27%↓** | 98.18% | **50.00%↓** | 85.00% | 95.00% | 135.16 ms |
| ② + BM25 / RRF 混合召回 | 69.09% | 81.82% | 94.55% | 65.00% | 85.00% | **100.00%** | 146.49 ms |
| ③ + 交叉编码器重排 | **96.36%** | **98.18%** | **100.00%** | **80.00%** | **100.00%** | 100.00% | 265.09 ms |
| ④ + 无证据兜底（复跑） | 96.36% | 98.18% | 100.00% | 80.00% | 100.00% | 100.00% | 261.47 ms |

**结论：切分和混合召回都不是主要杠杆，重排才是；但切分是重排能生效的前提。**

- ① 单独上 QA 切分时 easy Span@3 掉了 7.28 个百分点、hard Span@1 掉了 5 个百分点——chunk 从 66 变 145、粒度变细之后，纯向量的语义相似度把正确答案挤到了第 4–7 位。**如果做到这一步就收工，会得出「切分没用」的错误结论。**
- ② 混合召回主要补「找不找得到」：easy Top-8 未命中 1 → 0、hard Source@8 95% → 100%；但「排不排得上」反而更差，easy Span@3 再掉到 81.82%、hard 仍有 3 题未命中。BM25 的价值是把型号、错误码这类关键词强命中的块拉进候选池，代价是候选池里同类相邻块也变多了。
- ③ 重排一次性把 easy Span@1 拉到 96.36%（+27.27 个百分点）、hard Span@3 拉到 100%（+15 个百分点），两边 Top-8 未命中都归零。
- ④ 兜底不改检索结果，复跑与 ③ 完全一致，用来确认「加阈值判断没有误伤召回」。

### 3.4 无证据阈值标定

`min_score` 决定「检索到的东西算不算证据」。这个数不是拍的，由 `eval/calibrate_min_score.py` 跑 easy 80 + hard 25 = 105 道题的真实管线标定（k=3，结果文件 `eval/results/min_score_calibration.*`）：

| 分组 | 样本 | 最低分 | P5 | P50 | 最高分 |
|---|---|---|---|---|---|
| answerable | 75 | **0.1673** | 0.1948 | 0.5273 | 0.9510 |
| negative（未被路由拦下） | 5 | 0.1261 | 0.0061 | 0.1473 | **0.1578** |
| negative（已被 `scope_router` 拦下） | 15 | 0.0061 | - | - | 0.4521 |
| report | 10 | 0.0801 | 0.0801 | 0.1398 | 0.1798 |

- 两组可分，间隔 **0.0095（约 4% 余量）**；脚本建议取中点 **0.1626**，实际配 **0.16**（偏向少误伤可答题）。
- **已被路由拦下的 15 条 negative 不参与阈值计算**：它们根本走不到重排，算进来会把阈值抬到 0.45 以上、误伤一大片可答题。第一版标定就是因为没区分这点，报出了 `separable: false`。
- `report` 组最低分 0.0801 低于阈值，但报告走 `report_pipeline`、不经过 RAG 检索，不受影响。
- 实跑复核（2026-11-13）：5 道 in-scope 负样本全部 `docs=0`、返回 `NO_EVIDENCE_ANSWER`、**不调用生成模型**（最高分 0.1578 / 0.1487 / 0.1473 / 0.1355 / 0.1261）；分数最低的两道可答题 `hard-qa-016`（0.1673）与 `qa-008`（0.1811–0.1812）仍各保留 1 条片段并正常作答。
- 同一题连跑 3 次，重排最高分在 **±0.0001** 级抖动（0.1812 / 0.1811 / 0.1812）；远小于 4% 余量，不会翻转判定，但标定值本身带测量噪声。
- **换语料、换重排模型或改切分参数后必须重跑标定。**

- `qa-042`「拖布多久清洗一次」：目标是 `扫拖一体机器人100问.txt` 的 Q3，200 字硬切把 Q1/Q2/Q3 挤进同一个 chunk，主题被稀释，召回的是 Q12/Q13 等相邻主题。**M2-A 的 QA 感知切分单独就修好了这题（未命中 → Span@1）**，回答级 correctness 从 0 → 1 → 2。
- `hard-qa-007`「老人不想用手机 App，选机型看哪些操作方式」：问法已偏离原文的「语音控制/实体按键」。**M2-C 重排后 Span@1**。
- `hard-qa-016`「小孩在家，边刷和 App 分别防什么」：跨章节组合（安全 + App），固定字符 chunk 没有同时覆盖两部分。**M2-C 重排后 Span@1**。

#### pass^k：M2 前（2026-11-07）与 M2 后（2026-11-13）

同题独立跑 3 次（`--repeat 3`）。结果文件：M2 前 `hard_pass3.*` / `report_pass3.*`，M2 后 `hard_pass3_post_m2.*`。

| 数据集 | 题数 | 严格 pass^3（M2 前 → 后） | 至少一次通过 | 平均单次通过（M2 前 → 后） | 波动题（M2 前 → 后） |
|---|---|---|---|---|---|
| hard answerable | 20 | 95.00% → **100.00%** | 100.00% → 100.00% | 96.67% → **100.00%** | 1 → **0** |
| hard negative | 5 | **60.00% → 100.00%** | 100.00% → 100.00% | 86.67% → **100.00%** | 2 → **0** |
| hard 合计 | 25 | **88.00% → 100.00%** | 100.00% → 100.00% | 94.67% → **100.00%** | 3 → **0** |
| easy report | 10 | **100.00%**（未重跑） | 100.00% | 100.00% | 0 道 |

M2 前 hard negative 单次是 5/5、严格 pass^3 只有 3/5，两次失败都是「没有明确拒绝，而是继续给跨领域操作建议」（`hard-neg-002` 补了「越障高度 1.5–2 cm」，`hard-neg-004` 说「不确定是否支持」之后继续给充电注意事项）。报告题 pass^3 全过且零波动，说明确定性报告子流程把控制流固定后稳定性显著优于旧 ReAct 链路。

M2 后两侧的 100% 成因不同，**不能合并成一句「M2 让稳定性变好了」**：

- **answerable 是检索真修好了。** 唯一的旧波动题 `hard-qa-016`（儿童锁 + 边刷防护）从 `pass_count=1`、三轮 correctness 0/0/1、判分理由「未提及儿童锁和边刷防护」，变成 3/3 全 correctness=2；它在 M2 前属于 Top-8 完全召不回片段的类别。20 道可答题全部拿到 1–3 条真实引用，**兜底零误伤**——逐题查过 `sources` 长度和回答文本，没有一条命中 `NO_EVIDENCE_ANSWER`。这一条必须查，因为兜底是个会短路的开关，阈值偏高时它会静默把可答题也变成拒答，而那样 pass 率反而更好看。
- **negative 的 100% 是兜底送的，不是模型更会拒答。** 15/15 次运行返回逐字相同的 `NO_EVIDENCE_ANSWER`、`sources=0`，生成 P50 1234ms → 352ms（P95 2031ms → 919ms），说明重排最高分低于 `min_score=0.16`，`rag_service.py` 的 `if not context_docs` 分支直接返回、没进 `chain.invoke`。固定模板不可能波动，严格 pass^3 是**结构上必然 100%**。把拒答从「指望模型自觉」改成「代码短路」才是波动归零的原因，这是工程手段换来的稳定性。

顺带量出一个此前没记录的口径噪声：上表之外的「完全正确 / 完全有据」是**每题取一次代表性判分**，不是三轮聚合。同一份代码、同一个 145 chunks 语料，`hard_answer_m2.json`（repeat=1，01:44）是完全正确 95% / 完全有据 95%，`hard_pass3_post_m2.json`（repeat=3，13:58）是 85% / 100%——差 10 个百分点且方向相反。逐题对照：repeat=1 只有 `hard-qa-014` 落在 corr=1，repeat=3 是 `hard-qa-004`、`-014`、`-017`；三轮内部本身就不一致（`hard-qa-003` 是 2/1/1，`hard-qa-004` 是 1/1/2）。20 题的小集上一道题就是 5 个百分点，判分又和生成同为 `qwen-max`。**所以两处都保留原数字并注明口径，不要用单次跑的正确率下结论，也不要拿它覆盖另一次的结果。**

## 4. 复现

```bash

  --out eval/results/hard_answer.json

python eval/run_answer_eval.py --dataset eval/dataset_hard.jsonl \
  --repeat 3 --out eval/results/hard_pass3_post_m2.json

# k 敏感性：只改回答级检索条数
python eval/run_answer_eval.py --dataset eval/dataset_hard.jsonl \
  --k 5 --out eval/results/hard_answer_m2_k5.json

# 标定无证据阈值（真实调用 embedding + 重排，约 40 秒）
python eval/calibrate_min_score.py

# 检索 A/B：改 config/rag.yml 的 retrieval.mode / rerank.enabled 后重跑检索基线

#   mode: hybrid + rerank.enabled: false  → 只看混合召回
```

## 5. 新增题目

1. 在 `eval/dataset.jsonl` 追加一行，`id` 不重复；
2. 填 `gold_sources` + `gold_sections`/`gold_terms`，**不要写 chunk id**；
3. 跑 `--validate-only`，它会检查每个章节/关键词是否仍能在对应源文件中找到；
4. 跑评测，确认新题不会因为标签错误制造假失败。

## 6. 限制与下一步

- **easy / hard 分开报**：easy 多数题目来自知识库原问句，分数偏高；hard 是改写与跨节组合，25 题样本仍小，不能当作真实用户分布。
- **同源判分**：生成与判分默认都是 `qwen-max`，存在自偏好；已用 gold answer、明确 rubric 与 `temperature=0` 降低，但未做人工双标与一致性系数。
- **粗粒度 rubric**：correctness / faithfulness 是 0/1/2，同一条回答跨运行可能有 1 分波动；hard split 用 pass^3 暴露波动，easy 目前只跑单次。
- **单 gold 集合**：真实场景可能有多个正确片段；当前 Recall@k 等价于 hit rate。
- **报告字段是词面下界**：标签 + 数值 + 单位归一能抓漏字段，但不判断语义等价；方向与编造交给 LLM judge。
- **报告题都显式给出 user_id / month**：`get_user_id` / `get_current_month` 的随机 mock 分支未被覆盖。
- **报告生成 P50 约 6.9 秒**：确定性流程已去掉选工具往返，剩余成本主要是最终报告的输出长度；SSE 已把首 token 降到 0.4–0.8 秒，但完整回答仍要 5–12 秒。
- **拒答有三层，评测只报合并结果**：① `scope_router` 规则拦下的 easy 15 道（0 token）；② 重排分低于 `min_score` 的无证据兜底（覆盖 hard 5 道能力边界负样本，同样 0 token）；③ 剩下才交给模型判断。当前指标不区分是哪一层生效，所以「拒答正确率 100%」不等于模型的边界判断能力是 100%。
- **规则路由有覆盖边界**：`is_report_query` 只覆盖显式报告词和「ID + 月份 + 数据词」，换一种完全不含这些词的说法会回退 ReAct；用 80 题逐题断言路由结果做回归。
- **两种检索口径**：检索基线用 k=8 看召回上限；回答级用 k=3 复现生产链路，不能直接相减。
- **`min_score` 余量只有约 4%**：answerable 最低 0.1673、in-scope negative 最高 0.1578，可分但很薄；扰动测试只做了 1 题 × 3 次（重排分抖动 ±0.0001），没有覆盖全部边界样本，也没有按问题类型分档。
- **重排降级路径只做了单测**：真实限流 / 超时下的端到端表现没测，降级只有日志与 stats 字段，没有告警，质量掉分不会报错。
- **BM25 索引是进程内的**：多 worker 部署时各自建索引，语料更新后没有跨进程失效机制，只在单进程下验证过。
- **切分只在当前 5 个 txt 上验证**：`test_real_data_files_lose_no_line` 保证不丢行，但没验证新增文档类型（表格、Markdown 标题层级、PDF）时的切分行为。
- **下一步**：① M2 后重跑 hard `--repeat 3`，更新 pass^k（当前最该补的一格）；② easy 全量 pass^k；③ 扩大 hard split（更多跨章节组合、近似干扰项、错别字问法），并把越界路由准确率纳入同一套基线；④ 给重排降级加计数与告警；⑤ 报告链路继续做流式与更快模型。
